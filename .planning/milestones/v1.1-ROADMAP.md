# Milestone v1.1: Hardening

**Status:** SHIPPED 2026-05-15  
**Phases:** 13-17.1  
**Total Plans:** 20  
**Total Tasks:** 55

## Overview

v1.1 hardened the shipped libbsa library rather than broadening public scope. The milestone followed the order correctness boundary -> verification boundary -> structural cleanup -> hotspot hardening -> ship gate, then added Phase 17.1 to close audit-discovered tech debt before archival.

## Phases

### Phase 13: Host Path Correctness Boundary

**Goal:** Consumers and maintainers can trust archive open and validation flows on Windows host paths that contain non-ASCII characters.  
**Depends on:** Phase 12  
**Requirements:** HOST-01, HOST-02, HOST-03  
**Plans:** 5 plans

Plans:
- [x] 13-01: Rename and generalize the shared host-file helper into the locked `host_file` family and remove old helper names.
- [x] 13-02: Introduce the shared internal `host_file_path` contract and migrate the shared helper plus writer call sites onto it per D-14.
- [x] 13-03: Resolve and store host paths once at open time, then migrate parser contracts and parser opens onto that boundary.
- [x] 13-04: Rewire reader reopens and validation setup onto the single stored host-path boundary while preserving public semantics.
- [x] 13-05: Prove non-ASCII host-path open, validation, and canonical extraction with one dedicated cross-family regression suite.

**Details:** Implemented shared host-file and host-path seams, migrated reader/parser/validation paths, and added black-box non-ASCII host-path regression coverage.

### Phase 14: Verification Lane Truthfulness

**Goal:** Maintainers can rely on the documented hardening lanes because the supported Release and ASan flows are checked in, runnable, and consistently described.  
**Depends on:** Phase 13  
**Requirements:** VER-01, VER-02, VER-03  
**Plans:** 3 plans

- [x] 14-02: Reshape GitHub Actions into the supported debug/release matrix plus a separate MSVC AddressSanitizer hardening job.
- [x] 14-03: Align README, fixture policy, and planning summaries with the supported matrix and close the truthfulness gate across every named surface.

**Details:** Added checked-in Release static/shared and MSVC ASan preset triads, CTest-owned package proof, workflow topology, runtime DLL handling, and policy tests to keep docs, CI, presets, and planning aligned.

### Phase 15: Reader Backend Dispatch Cleanup

**Goal:** Reader behavior is selected once at open time so consumers see unchanged archive operations while maintainers stop repeating family dispatch logic across the public reader surface.  
**Depends on:** Phase 14  
**Requirements:** DISP-01, DISP-02  
**Plans:** 1 plan

Plans:
- [x] 15-01: Introduce one open-time-selected file-local reader backend seam in `src/archive.cpp` and lock it with dedicated runtime plus policy regression suites.

**Details:** `archive_reader::open` now selects a backend table once and public reader operations reuse it for entries, lookup, extraction, extract_bytes, and bulk extraction.

### Phase 16: Parser and Preparer Seam Extraction

**Goal:** The targeted TES4 parser and BA2 DX10 preparer hotspots become smaller internal seams that are safer to change because behavior is locked down by focused regression coverage.  
**Depends on:** Phase 15  
**Requirements:** REFA-01, REFA-02

- [x] 16-02: Extract BA2 DX10 snapshot builder and chunk assembler seams with focused TDD regression coverage.
- [x] 16-03: Add role-based seam policy guardrails and run the Phase 16 verification sweep.

**Details:** Split TES4 parser responsibilities into raw-table and payload-descriptor seams, split BA2 DX10 preparation into snapshot-builder and chunk-assembler seams, and added source-policy guardrails against coordinator collapse.

## Milestone Summary

**Decimal Phases:**
- Phase 17.1: Address Tech Debt in v1.1 Milestone Audit (inserted after Phase 17 for urgent audit follow-up)

**Key Decisions:**
- Keep v1.1 as a hardening-only milestone with no public API expansion.
- Resolve Windows host paths once through shared internal host-file seams.
- Treat Release and MSVC ASan lanes as checked-in, CTest-backed verification contracts.
- Keep parser/preparer hotspot extractions private and policy-guarded.
- Keep dedupe candidate filters non-authoritative; exact final stored-byte equality remains the sharing gate.
- Treat BA2 DX10 snapshot cleanup as best-effort ordinary-path cleanup with documented residual abnormal-termination risk.
- Close audit follow-up with source/test/verification evidence rather than mutating the audit source during implementation.

**Issues Resolved:**
- Non-ASCII Windows host-path drift across archive open, validation, parser, extraction, and reader-surface paths.
- Verification lane drift across presets, CI, docs, planning, and package-consumer proof.
- Repeated reader family dispatch across public reader operations.
- Oversized TES4 parser and BA2 DX10 preparer hotspots.
- TES4 and BA2 GNRL dedupe hotspot candidate scans while preserving exact equality.
- BA2 GNRL disk-backed dedupe raw path reopening.
- BA2 DX10 snapshot temp data lingering after ordinary write completion and result-returning failures.
- Prior audit warnings about split coverage, unused private state, and writer host-path disposition.

**Issues Deferred:**
- Optional sample CLI remains a future-scope candidate.
- Public fuzzing harnesses remain a future-scope candidate.
- Lenient corrupt-archive recovery mode remains a future-scope candidate.
- Stable binary ABI policy remains a future-scope candidate.
- Eight missing quick-task tracking artifacts were acknowledged at milestone close and recorded in `STATE.md`.

**Technical Debt Incurred:**
- BA2 DX10 abnormal termination cleanup remains an explicitly documented residual risk.
- Current checkout at audit time had uncommitted formatting-only public-header drift in `include/libbsa/archive.hpp` and `include/libbsa/result.hpp`; those files were not part of the milestone archival scope.
