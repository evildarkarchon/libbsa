<decision_coverage>
- D-01: `entry_metadata` receives a DX10-only optional texture value rather than a separate public reader or lookup API.
- D-02: Public texture metadata remains dependency-light and minimal, with value structs and no helper display APIs or broad public enums.
- D-03: Texture format is represented as a raw numeric DXGI format identifier.
- D-04: Texture metadata exposes explicit dimensions, mip count, array size, and cubemap state.
- D-05: Public per-entry DX10 chunk metadata exposes payload offsets, stored/raw sizes, mip ranges, and compression route through libbsa-owned types.
- D-06: Future DX10 `entry_metadata::raw_size` documentation states the consumer-visible extracted DDS size including the reconstructed header.
- D-07: Raw archive-derived DX10 fields that affect reconstruction or compatibility evidence are preserved as clearly named libbsa-owned metadata.
- D-08: The optional texture metadata remains populated only for BA2 DX10 entries; existing BSA and BA2 GNRL entries keep `std::nullopt` semantics.
- D-25: A reusable internal texture analyzer boundary is added for Phase 6 DDS validation and future Phase 9 extension.
- D-26: DirectXTex is linked privately and public headers stay free of DirectXTex, DXGI, Windows SDK, and private dependency types.
- D-27: Internal analyzer APIs immediately translate DirectXTex metadata into libbsa-owned values and do not pass DirectXTex types across module seams.
- D-28: The analyzer boundary is reusable by shape only; this plan does not implement DDS input parsing for BA2 writing or writer-side chunk generation.
</decision_coverage>
