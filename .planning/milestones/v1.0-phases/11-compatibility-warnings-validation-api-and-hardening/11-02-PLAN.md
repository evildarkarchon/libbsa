<interfaces>
Existing strict reader contract:
```cpp
static result<archive_reader> archive_reader::open(std::string_view host_path);
[[nodiscard]] result<archive_metadata> metadata() const;
[[nodiscard]] result<std::vector<entry_metadata>> entries() const;
[[nodiscard]] result<std::vector<std::byte>> extract_bytes(std::string_view path) const;
```

Validation behavior to implement:
- Empty `host_path` returns result-level `error_code::invalid_argument`.
- Missing or unreadable host files return result-level `error_code::io_error`.
- Readable unsupported or malformed archive bytes return `result<validation_report>` with `valid == false`, `metadata == std::nullopt`, and one fatal `validation_diagnostic` in `errors`.
- Valid archives return `valid == true`, populated `metadata`, and no fatal errors unless `validate_entry_extractability` finds extraction/decompression failures.
- `archive_reader::open` behavior is not weakened or wrapped into a lenient reader.
</interfaces>
</context>

<decision_trace>
- D-01: `src/validation.cpp` implements the public `validate_archive` entry point.
- D-02: `archive_reader::open` remains the strict parser/open path and malformed archives do not become usable readers.
- D-03: Inspectable archive failures become `validation_report.errors`; setup failures stay result-level errors.
- D-04: The report exposes validity, metadata, errors, and warnings without entry listing, extraction bytes, or a second reader API.
- D-05: Implementation honors only expected type/variant and opt-in extractability validation options.
- D-16: Implementation keeps private parser/compression types out of public headers.
- D-17: Tests assert `error_code` values and report structure rather than exact diagnostic strings.
- D-18: Generated fixtures and writer-produced archives are the mandatory validation evidence.
</decision_trace>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host filesystem -> validation facade | Caller-controlled paths may be empty, missing, unreadable, or point to arbitrary bytes. |
| archive bytes -> strict parser | Untrusted archive headers, counts, offsets, names, compression metadata, and DDS chunks cross into existing parsers. |
| parser errors -> public diagnostics | Private parse failures become stable public report diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-04 | Denial of Service | validate_archive extraction validation | mitigate | Keep extractability validation opt-in through `validation_options::validate_entry_extractability`; use existing bounded `archive_reader` extraction paths. |
| T-11-05 | Tampering | malformed archive diagnostics | mitigate | Preserve `archive_reader::open` strict failure and translate only stable `error_code` categories into `validation_report.errors`. |
| T-11-06 | Information Disclosure | validation_report | mitigate | Do not include byte offsets, record indexes, chunk indexes, or private parser details in public report types. |
</threat_model>
