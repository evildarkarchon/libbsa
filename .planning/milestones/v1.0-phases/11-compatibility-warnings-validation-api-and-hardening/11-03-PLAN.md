<interfaces>
Warning scenarios locked for initial coverage:
- `compatibility_warning_code::target_family_mismatch`, `compatibility_warning_severity::risky`, no `archive_path`, triggered when `validation_options::expected_type` or `expected_variant` disagrees with parsed metadata.
- `compatibility_warning_code::bsa_embedded_name_compatibility_risk`, `compatibility_warning_severity::risky`, entry `archive_path` present, triggered for BSA entries with `entry_metadata::has_embedded_name == true`.
- `compatibility_warning_code::compressed_sound_payload`, `compatibility_warning_severity::advisory`, entry `archive_path` present, triggered for compressed entries whose normalized path starts with `sound/` or has a sound-like extension `.wav`, `.xwm`, or `.fuz`.
</interfaces>
</context>

- D-06: Warning policy emits stable `compatibility_warning_code` values.

- D-08: Warning severity uses the two public values `advisory` and `risky`.
- D-09: Warning records do not expose byte offsets, record indexes, or chunk indexes.
- D-10: Warning tests assert codes, severity, and optional path presence rather than exact messages.
- D-11: Initial warning scenarios span BSA and BA2 families using generated or writer-output evidence.
</decision_trace>
