<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archive metadata bytes→TES3 parser | Untrusted counts, offsets, names, and hashes drive allocation and metadata materialization. |
| parsed names→path normalizer | Archive-provided names become public lookup keys and must reject ambiguous paths. |
| stored hash records→entry metadata | Hashes can be forged or reordered to hide wrong names/content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-09 | Tampering / DoS | TES3 table parser | mitigate | Use checked little-endian reads, checked count×width arithmetic, section span validation, and `format_error` on truncation. |
| T-04-10 | Tampering | raw offset conversion | mitigate | Convert `data_section_start + raw_offset` with overflow/span checks and store only archive-absolute offsets per D-01/D-04. |
| T-04-11 | Tampering | path normalization | mitigate | Normalize with `detail::normalize_archive_path`; reject duplicate canonical paths and invalid syntax. |
| T-04-12 | Tampering | TES3 hash table | mitigate | Validate stored hash from parsed name spelling, reject mismatches, collisions, and unsorted low32/high32 records. |
| T-04-13 | Denial of Service | file count / name offsets | mitigate | Bound allocations and require each name offset to resolve to a non-empty null-terminated name before the hash table. |
</threat_model>
