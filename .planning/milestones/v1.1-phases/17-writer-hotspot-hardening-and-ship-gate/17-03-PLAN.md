  <behavior>
    - Successful ba2_dx10_writer::write_to removes newly created writer-owned libbsa-dx10-snapshot-* directories before the writer object is destroyed.
    - Validation failure, missing or truncated snapshot data before publish, and output or publish failure remove newly created writer-owned snapshot directories before write_to returns.
    - Failed add_file calls that reserved the first snapshot directory remove that directory before returning an error.
    - Cleanup is best-effort and never replaces the primary result error from validation, write, or publish failures.
    - After any ordinary write_to attempt, later add_file and write_to calls return error_code::invalid_argument through result.
  </behavior>
  <implementation>Add consumed tracking and an explicit noexcept cleanup helper to ba2_dx10_writer::state. Mark only BA2 DX10 consumed on write_to attempts, run cleanup after write_ba2_dx10_archive returns, preserve the saved primary result, and keep destructor cleanup as a safety net. In add_file, if a snapshot directory was empty before the call and a subsequent entry creation failure occurs, clean up that newly reserved directory before returning the original error.</implementation>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DDS host file -> snapshot temp directory | Caller-provided DDS bytes are copied into writer-owned temporary files. |
| writer pipeline -> destination publish | Write and publish errors cross from internal temp files to public result errors. |
| writer object after write attempt | Public mutation/finalization calls occur after snapshot data has been cleaned. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-07 | I | src/formats/ba2/ba2_dx10_writer.cpp | mitigate | Explicitly remove writer-owned snapshot_dir on success and ordinary result failures before writer destruction. |
| T-17-08 | R | src/formats/ba2/ba2_dx10_writer.cpp | mitigate | Preserve primary result errors when cleanup fails so callers receive validation, write, or publish failure evidence. |
| T-17-09 | T | src/detail/writer_publish.cpp interop | mitigate | Keep detail::publish_writer_output as output publication boundary and run snapshot cleanup around, not instead of, the publish result. |
| T-17-10 | E | ba2_dx10_writer consumed state | mitigate | Return invalid_argument on post-consumption add_file/write_to so stale staged entries cannot be partially reused. |
</threat_model>
