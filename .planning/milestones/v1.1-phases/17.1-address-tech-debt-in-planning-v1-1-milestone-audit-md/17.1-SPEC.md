# Phase 17.1: v1.1 Milestone Audit Tech Debt - Specification

**Created:** 2026-05-14
**Ambiguity score:** 0.16 (gate: <= 0.20)

## Goal

The non-blocking v1.1 milestone audit tech debt changes from open cleanup warnings into committed regression coverage, explicit unused-state dispositions, and a bounded writer-host-path disposition without expanding v1.1 product scope.

## Background

Phase 17 completed the v1.1 ship gate with all mapped requirements satisfied, all integration checks wired, all E2E flows complete, and no milestone-blocking gaps. `.planning/v1.1-MILESTONE-AUDIT.md` still reported `tech_debt` because several low-severity follow-up items remained after acceptance: Phase 13 non-ASCII host-path coverage and Phase 15 full reader-surface dispatch coverage are split across separate suites; `detail::host_file_path::original_utf8` is currently diagnostics-only state; `archive_reader::state` stores `backend_identity` beside the active backend table even though public operations dereference `backend_table`; and broader writer-side host-path hardening was left future-scope unless promoted.

The codebase scout confirms the split coverage: `tests/unit/host_path_correctness_boundary_tests.cpp` copies representative archives under non-ASCII host paths and proves open, validation, and a minimal extraction path, while `tests/unit/archive_reader_dispatch_tests.cpp` exercises `entries`, `find`, `contains`, `extract`, `extract_bytes`, and `extract_entries` across representative backends from normal fixture paths. `src/detail/host_file_path.hpp` stores `original_utf8` and `resolved`, with tests proving preservation but not a diagnostic consumer. `src/archive.cpp` keeps both `reader_backend_identity backend_identity` and `const reader_backend* backend_table` in reader state, while public reader methods only use `backend_table` and policy tests forbid `backend_identity` in those public-method bodies. Writer-side paths already use `detail::host_file_path` in several source/output flows, including Phase 17 BA2 GNRL disk-backed dedupe remediation, but the audit still needs a bounded disposition of the remaining writer-host-path warning.

## Requirements

1. **Combined non-ASCII reader-surface regression**: Add one focused public-API regression that combines the Phase 13 non-ASCII host-path boundary with the Phase 15 reader dispatch surface.
   - Current: Non-ASCII host-path open/validate/extract coverage and full reader-surface dispatch coverage live in separate suites, so no test proves that a copied non-ASCII fixture can flow through `entries`, `find`, `contains`, and `extract_entries` in one scenario.
   - Target: A committed test copies at least one existing supported archive fixture under a non-ASCII Windows host path, opens it through `archive_reader::open`, and exercises `entries`, `find`, `contains`, and `extract_entries` through the public API using existing fixture manifest expectations.
   - Acceptance: The focused test fails if the non-ASCII copied archive cannot be opened, if `entries` does not match the manifest count or expected path, if `find` or `contains` cannot locate the canonical entry, or if `extract_entries` cannot extract the expected payload bytes from the non-ASCII host path.

2. **Host-path diagnostics state disposition**: Resolve the audit warning for `detail::host_file_path::original_utf8` so it is not retained as unconsumed diagnostics-only state.
   - Current: `host_file_path` stores `original_utf8`, comments describe diagnostics intent, and `host_file_path_tests.cpp` proves the bytes are preserved, but helper I/O paths use `resolved` and no committed test proves a diagnostic or policy consumer of `original_utf8`.
   - Target: `original_utf8` is either consumed by a verified private diagnostic or policy path, or removed from the internal host-file path contract if it remains unnecessary. The public `std::string_view` host-path API remains unchanged.
   - Acceptance: A verifier can point to committed source and test/policy evidence showing either a real `original_utf8` consumer with pass/fail coverage, or no remaining `host_file_path::original_utf8` member and no stale comments/tests claiming preserved diagnostics-only state.

3. **Reader backend identity disposition**: Resolve the audit warning for `archive_reader::state::backend_identity` without reintroducing repeated public-reader family dispatch.
   - Current: `archive_reader::state` stores `backend_identity` next to `backend_table`; `entries`, `find`, `contains`, `extract`, `extract_bytes`, and `extract_entries` dereference only `backend_table`; and `archive_reader_dispatch_policy_tests.cpp` forbids `backend_identity` in public reader method bodies.
   - Target: `backend_identity` is either removed from reader state as unused private state, or consumed by a verified private diagnostic or policy path outside the public reader method bodies. The one open-time backend seam and existing reader behavior remain unchanged.
   - Acceptance: A verifier can point to committed source and test/policy evidence showing that `backend_identity` is no longer unused state, that public reader operations still avoid repeated archive-family branching, and that representative reader-dispatch runtime coverage still passes.

4. **Writer host-path audit disposition**: Bound and close the remaining writer-side host-path warning from the audit without turning Phase 17.1 into a full writer redesign.
   - Current: Phase 13 verification flagged writer-side raw path reopen concerns outside the read/open/validate scope; Phase 17 remediated BA2 GNRL disk-backed dedupe comparisons to use resolved host paths; existing writer tests cover several non-ASCII source/output flows, but the audit still records broader writer-side host-path hardening as future-scope unless promoted.
   - Target: The phase inventories the currently supported writer source, output, finalization, and dedupe host-file I/O paths touched by TES3 BSA, TES4-family BSA, BA2 GNRL, and BA2 DX10 writers, then records an explicit disposition: no promoted implementation gap remains for v1.1, a narrowly found raw host-path reopen is migrated behind the shared host-file boundary, or a specific future requirement is recorded outside Phase 17.1.
   - Acceptance: Final verification cites the source, test, policy, or planning evidence used for the writer-host-path disposition, and the phase does not finish with the audit warning still vague or unactioned.

## Boundaries

**In scope:**
- One combined public-API regression that proves non-ASCII host-path open plus reader-surface dispatch behavior for an existing supported fixture.
- Internal cleanup or verified consumption of `detail::host_file_path::original_utf8`.
- Internal cleanup or verified consumption of `archive_reader::state::backend_identity`.
- Bounded writer-host-path inventory and disposition for currently supported writer source, output, finalization, and dedupe flows.
- Focused runtime and/or source-policy tests that make the tech-debt closure falsifiable.
- Planning or verification evidence that records which audit items were closed, accepted, or deferred.

**Out of scope:**
- Crash-proof, hard-termination-proof, OS-shutdown-proof, or externally enforced cleanup for BA2 DX10 snapshot directories - Phase 17 explicitly documented this as accepted residual risk.
- Public API redesign, new public path overloads, new reader/writer public types, or new diagnostics APIs - v1.1 remains hardening-only.
- A full writer architecture rewrite or broad performance program - this phase only dispositions audit warnings.
- New archive family support, new DDS feature support, new compression behavior, or changed archive-format semantics - the audit debt is cleanup and coverage, not product expansion.
- Replacing the Phase 15 open-time backend seam with a plugin, registry, or extensibility framework - the existing private seam remains the intended architecture.
- Broad real-corpus compatibility workflows, fuzzing harnesses, or lenient corrupt-archive recovery - these remain future requirements outside v1.1.
- Modifying, formatting, staging, or compiling files under `TES5Edit/` - the submodule remains read-only reference material.
- Cross-platform portability work - libbsa remains Windows-only.

## Constraints

- Preserve the public C++20 API in `include/libbsa/`; this phase must not add public host-path, reader-backend, writer, or diagnostics surface area.
- Preserve existing consumer-visible behavior for supported archive readers and writers, including current error-code semantics for invalid archive paths, missing entries, writer failures, and validation failures.
- Keep all host-path handling Windows-oriented and routed through the existing internal host-file boundary where filesystem I/O is involved.
- Do not introduce external dependencies beyond the approved vcpkg stack.
- Keep implementation work outside `TES5Edit/`.
- Treat BA2 DX10 abnormal-termination cleanup as already accepted residual risk unless a later phase explicitly changes the requirement.
- Prefer focused tests or policy guardrails over broad new suites; this phase should close specific audit warnings, not reopen the shipped v1.1 milestone.

## Acceptance Criteria

- [ ] A committed test opens an existing supported archive copied under a non-ASCII host path and exercises `entries`, `find`, `contains`, and `extract_entries` through public APIs with manifest-backed expected results.
- [ ] `detail::host_file_path::original_utf8` is either removed from the internal contract or has a committed, verified consumer; no stale comments or tests describe unused diagnostics-only state.
- [ ] `archive_reader::state::backend_identity` is either removed from reader state or has a committed, verified consumer outside public reader method bodies.
- [ ] Public reader operations still use one open-time backend seam and do not regain repeated archive-family branching in `entries`, `find`, `contains`, `extract`, `extract_bytes`, or `extract_entries`.
- [ ] The writer-side host-path audit warning is closed with cited source/test/policy evidence, a narrowly migrated raw host-path reopen, or a specific future requirement recorded outside Phase 17.1.
- [ ] Existing representative reader dispatch and host-path boundary coverage still passes after the cleanup.
- [ ] No public headers in `include/libbsa/` gain new path, reader-backend, writer, or diagnostics APIs for this phase.
- [ ] No files under `TES5Edit/` are modified, staged, or committed.
- [ ] No new external dependencies are introduced.
- [ ] Verification or summary evidence records the final disposition of each Phase 17.1 audit item, including the accepted BA2 DX10 abnormal-termination residual risk staying out of scope.
