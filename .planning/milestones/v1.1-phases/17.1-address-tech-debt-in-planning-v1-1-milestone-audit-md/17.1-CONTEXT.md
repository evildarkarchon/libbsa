<decisions>
## Implementation Decisions

### Unused state disposition
- **D-01:** Remove `detail::host_file_path::original_utf8` from the internal host-file path contract. Do not add a new private diagnostic consumer in Phase 17.1.
- **D-02:** Remove `archive_reader::state::backend_identity` from reader state. It may remain as file-local open-time table-selection plumbing only if needed, but it must not be stored beside the active backend table.
- **D-03:** Apply strict cleanup with the removals: remove or rewrite comments and tests that claim diagnostics-only preservation, and update policy evidence so the removed unused members do not quietly return.
- **D-04:** The removal decision is locked. If future diagnostics need original UTF-8 host-path text or reader backend identity, that belongs to a later requirement rather than this cleanup phase.

### Combined non-ASCII reader regression
- **D-05:** Add a reader-matrix combined regression rather than a single-fixture smoke test. The matrix should reuse the current representative reader families from Phase 15 where practical, but it should not recreate every family-specific edge case.
- **D-06:** The combined regression should cover the SPEC surface only: `entries`, `find`, `contains`, and `extract_entries` through the public API from archives copied under non-ASCII Windows host paths.
- **D-07:** Place the combined regression in `tests/unit/host_path_correctness_boundary_tests.cpp` so it reuses the non-ASCII path setup, UTF-8 conversion helper, fixture-copy pattern, and manifest expectations already established there.
- **D-08:** Keep the new regression success-path focused: manifest entry count/path expectations, canonical `find` and `contains`, and `extract_entries` payload bytes. Do not duplicate the negative missing-path or invalid-path dispatch matrix unless implementation uncovers a real gap.

### Writer host-path disposition
- **D-09:** Close the writer host-path audit warning through an explicit evidence inventory first. If the inventory shows supported writer I/O already routes through the shared host-file boundary, no broad writer redesign is needed.
- **D-10:** The inventory must explicitly cover the SPEC categories: TES3 BSA, TES4-family BSA, BA2 GNRL, and BA2 DX10 writer source, output, finalization, and dedupe host-file I/O paths.
- **D-11:** Final verification must cite the source, test, and/or policy evidence that closes each writer path category. Planning-only notes are not enough for closure.
- **D-12:** If the inventory finds a narrow raw host-path reopen in a currently supported writer source/output/finalization/dedupe path, migrate that specific reopen behind the shared host-file boundary in Phase 17.1.

### Proof and verification style
- **D-13:** Use both runtime and source-policy proof. Runtime tests should prove public reader behavior under non-ASCII paths; source-policy tests should prevent dead-state and raw-host-path boundary drift.
- **D-14:** Closure evidence should target focused Debug and MSVC AddressSanitizer lanes when touching host-path, reader dispatch, or writer I/O seams. Release package proof is not required unless packaging or public surface changes unexpectedly.
- **D-15:** Source-policy tests should guard negative invariants, not freeze exact helper names. Forbid specific bad patterns such as the removed state members or raw string reopens while allowing equivalent shared-host-file seam implementations.
- **D-16:** Do not update `.planning/v1.1-MILESTONE-AUDIT.md` directly as part of this phase. Audit artifact updates are handled by a dedicated slash-command after closure evidence exists.

### the agent's Discretion
None. The user selected concrete decisions for state removal, regression breadth, test location, writer audit closure, proof mix, verification lanes, policy strictness, and audit-file update handling. Downstream agents should not reopen these choices.

</decisions>

- `tests/unit/host_path_correctness_boundary_tests.cpp`: already owns the non-ASCII token, temp root cleanup, archive copy helper, UTF-8 path conversion, manifest parsing, expected-byte helpers, and a public-API-only policy test. Extend this file for the combined regression.

- `detail::resolve_host_file_path` in `src/detail/host_file_path.cpp`: remains the Windows UTF-8 resolution boundary, but should return a contract that no longer stores unconsumed caller text.
- `reader_backend_table` and the file-local `reader_backend` callbacks in `src/archive.cpp`: should remain the open-time reader dispatch seam while `archive_reader::state` drops unused backend identity storage.

### Established Patterns
- Public APIs under `include/libbsa/` stay stable and C++20-compatible; this phase must not add path overloads, diagnostics APIs, or public reader/writer types.
- Runtime tests prove public behavior with committed fixtures, while source-policy tests guard drift-prone internal invariants.
- Source-policy tests should be negative-invariant based: forbid stale members, raw reopen patterns, or repeated public dispatch without freezing exact helper names.
- Writer I/O should flow through `detail::host_file_path`, `detail::open_host_file`, and shared publish helpers instead of raw caller UTF-8 strings.
- Comments are part of the audit surface here: comments claiming diagnostics-only preservation must be removed or rewritten when the state they describe is removed.

### Integration Points
- `src/detail/host_file_path.hpp` and `src/detail/host_file_path.cpp`: remove `original_utf8` and update construction/return sites.
- `src/archive.cpp`: remove `backend_identity` from `archive_reader::state` while preserving one open-time selected `backend_table` and existing public reader semantics.
- `tests/unit/host_path_correctness_boundary_tests.cpp`: add the combined non-ASCII reader-surface matrix for `entries`, `find`, `contains`, and `extract_entries`.
- `tests/unit/host_file_writer_name_tests.cpp` and `tests/unit/archive_reader_dispatch_policy_tests.cpp`: update or add negative-invariant policy evidence for removed state and writer path-boundary closure.
- Writer inventory should inspect the TES3, TES4-family, BA2 GNRL, BA2 DX10, and `writer_publish` files listed in canonical refs and be cited in verification.
