## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo policy tests → repo text/config surfaces | untrusted drift can cause false verification claims if tests do not inspect each source independently |
| preset selection → compiler/linker flags | a preset name can claim ASan without enabling instrumentation |
| release `ctest` lane → downstream consumer package proof | internal-source tests can pass while installed-package behavior regresses |

| T-14-02 | R/I | `CMakeLists.txt`, `CMakePresets.json` | mitigate | Require checked-in `LIBBSA_ENABLE_MSVC_ASAN` and `/fsanitize=address` evidence so `windows-msvc-asan-static` cannot be a name-only hardening claim per D-01 through D-04. |
| T-14-03 | T | `tests/CMakeLists.txt`, `tests/package-consumer/*` | mitigate | Keep `package_consumer_smoke` and `package_consumer_runtime_dll_copy` inside the release `ctest` contract so package regressions cannot hide behind internal-source test success per D-05 through D-08. |
</threat_model>
