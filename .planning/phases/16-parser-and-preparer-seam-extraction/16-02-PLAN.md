<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DDS host file -> snapshot builder | Untrusted or changed host file bytes cross into texture analysis and writer-owned snapshot state. |
| Snapshot files -> chunk assembler | Staged snapshot files can be changed/truncated before final write; assembler must detect mismatches before publish. |
| Planned chunk descriptors -> compression router | Texture layout-derived chunk bounds and target compression options determine raw byte collection and compressed output. |
| Temp snapshot lifecycle -> filesystem | Abnormal termination can leave temp texture data behind; cleanup proof remains Phase 17 scope. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-03 | Tampering/Denial of Service | ba2_dx10_snapshot_builder | mitigate | Resolve/read DDS through detail host-file helpers, analyze immutable bytes, validate target format, and write fixed-size snapshot records. |
| T-16-04 | Tampering/Denial of Service | ba2_dx10_chunk_assembler | mitigate | Stream snapshot bytes with detail::for_each_host_file_chunk, check aggregate size against planned.raw_size, and fail before publish when snapshots are truncated/missing. |
| T-16-05 | Tampering | BA2 DX10 compression routing | mitigate | Preserve Fallout 4 deflate and Starfield v3 deflate/LZ4 method routing through existing compression router and focused tests. |
| T-16-06 | Information Disclosure | BA2 DX10 temp texture persistence | transfer | Do not claim abnormal-termination cleanup proof in Phase 16; keep DX10-01 and DX10-02 for Phase 17. |
</threat_model>
