## Shared Patterns

### Public API Comments

Public structs, helper functions, and methods added in Phase 7 should use concise Doxygen comments. Keep comments that explain why DirectXTex/DXGI details are represented as libbsa-owned values.

### Metadata-Only Archive Wrapper

`ba2_archive` already wraps `archive_view`. Extend it with copied texture metadata storage rather than borrowing from `byte_source`. `texture_metadata(path)` should normalize paths like `entry(path)` and return a copied value.

### Bounded Parser Helpers

Reuse the local style from `src/ba2_reader.cpp`: `checked_add`, `range_fits`, exact `read_bytes`, and little-endian helpers. Add DX10-specific record/chunk structs privately and keep comments near non-obvious field mapping.

### Compression Dispatcher

Do not call libdeflate or LZ4 directly from the DX10 extraction path unless a private codec helper already does so. Use `resolve_payload_codec` and `decompress_payload` with per-chunk state so deflate, LZ4 frame, and raw LZ4 block routes remain separated.

### Complete Buffer Before Sink Write

Follow existing no-partial-write tests by using `memory_sink` and malformed fixtures. DX10 extraction should build and validate the whole DDS byte vector before calling `sink.write(...)`.

### Test Fixture Style

Use generated source fixtures like Phase 6. Keep append/write helpers local to `tests/ba2_dds_fixture_helpers.*`, use named constants for versions/subtypes, and assert exact metadata plus DirectXTex semantic loadability.

## Anti-Patterns

- Do not expose raw DirectXTex or Windows SDK types in public headers.
- Do not add texture-only fields to generic `entry_metadata`.
- Do not mirror raw BA2 chunk records publicly when logical chunk summaries satisfy consumer inspection.
- Do not treat fixture blobs as opaque committed binaries.
- Do not expand Phase 7 into writer chunk generation, texture transcoding, or real corpus compatibility gates.
