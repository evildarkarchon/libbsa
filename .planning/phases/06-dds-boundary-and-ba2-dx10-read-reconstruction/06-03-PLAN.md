<decision_coverage>
- D-04: DDS layout tests and helpers consume explicit dimensions, mip count, array size, and cubemap state rather than requiring callers to inspect DDS flags.
- D-07: Layout values preserve raw DX10 fields needed for reconstruction assumptions without inventing unsupported semantics.
- D-09: DDS reconstruction always emits standard DDS magic/header plus a `DDS_HEADER_DXT10` extension.
- D-12: DDS layout utilities do not call DirectXTex as a runtime extraction success gate.
- D-15: Chunk validation computes DDS order from texture layout and rejects blind archive-order concatenation when coverage/order is invalid.
- D-16: Metadata-detectable layout problems such as gaps, duplicates, impossible coverage, and inconsistent ranges return `format_error` before extraction.
- D-18: DXT10 fields not clearly represented in BA2 records use conservative documented defaults.
</decision_coverage>
