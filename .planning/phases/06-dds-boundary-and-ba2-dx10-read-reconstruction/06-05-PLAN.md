- D-10: Extraction tests validate every generated reconstructed DDS output through DirectXTex and compare manifest dimensions, mip count, DXGI id, array size, and cubemap state.
- D-11: Tests compare decoded payload bytes after the reconstructed header against expected fixture payload order instead of requiring whole-file byte equality.
- D-12: Normal runtime extraction returns deterministic DDS bytes without calling DirectXTex before success.
- D-13: Sink-based extraction writes the reconstructed DDS header first, then decoded chunk payloads in validated DDS order with bounded per-chunk buffering.
- D-14: `extract_bytes(path)` returns exactly the same reconstructed DDS byte stream as `extract(path, sink)`.
- D-15: Extraction uses parser-validated DDS chunk order and never blind raw archive concatenation.
- D-17: Bad compressed chunks or exact decoded-size mismatches return `format_error` like BA2 GNRL behavior.
- D-30: Extraction preserves sink-first semantics and one-entry/one-chunk bounded buffering; whole-archive reads and broad performance work remain out of scope.
- D-31: Raw, deflate, and Starfield v3 raw-LZ4-block routing comes from parsed chunk metadata, never extension/path spelling.
- D-32: Each compressed DX10 chunk uses exact-size decompression validation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archive chunk bytes → decompressor | Compressed/raw bytes from archive are decoded or streamed into caller sink. |
| library extraction → caller sink | Caller-controlled sink can fail or accept partial writes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-15 | DoS/Tampering | compressed DX10 chunks | mitigate | Use `decompress_payload_exact` with parsed raw size; mismatch/corruption returns `format_error`. |
| T-06-16 | DoS | raw chunk reads | mitigate | Stream raw chunks with bounded buffer and validate short reads as `format_error`. |
| T-06-17 | Tampering | sink partial writes | mitigate | Treat partial sink acceptance as `io_error`, same as existing BA2 GNRL behavior. |
| T-06-18 | Tampering | codec selection | mitigate | Select raw/deflate/lz4_block from parsed metadata only; never infer from extension/path. |
</threat_model>
