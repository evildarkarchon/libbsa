<objective>
Close Phase 6 verification gaps for BA2 malformed name-table and empty-archive metadata handling.

Purpose: The Phase 6 verifier found D-16 still partial because duplicate normalized names can be collapsed by `archive_view::insert_or_assign`, and zero-entry BA2 archives can accept impossible `FileTableOffset` metadata. This plan makes both malformed cases fail before a `ba2_archive` is constructed.
Output: Two focused regression tests and parser hardening in `src/ba2_reader.cpp`.
</objective>

<decision_coverage>
- D-16: Completes malformed BA2 coverage for duplicate normalized names and impossible offsets without expanding into Phase 11 fuzz-style hardening.
- D-17: Reject duplicate BA2 names that normalize to the same archive path before constructing `ba2_archive` because `archive_view::insert_or_assign` would silently overwrite earlier records.
- D-18: Validate `FileTableOffset <= source.size()` even when `file_count == 0`; empty archives are allowed, impossible file table offsets are not.
- D-19: Add generated fixture tests in the existing BA2 reader style for exactly the duplicate-normalized-name and zero-entry impossible-FileTableOffset gaps.
</decision_coverage>
