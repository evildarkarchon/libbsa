<feature>
  <name>Post-policy data-region deduplication</name>
  <files>src/writer.cpp, tests/writer_core_tests.cpp</files>
  <behavior>
    - With `writer_options{.deduplicate = true}` and `supports_shared_data_regions = true`, entries `meshes/a.nif` and `textures/c.dds` with identical raw stored payload `{0x44,0x55}` reference the same `data_region_id` and same archive-absolute `offset`.
    - With `writer_options{.deduplicate = false}`, the same duplicate payload inputs have different `data_region_id` values and different offsets.
    - With `deduplicate = true` and `supports_shared_data_regions = false`, planning fails with `error_code::unsupported_format` and message `writer target does not support deduplication`.
    - Public plan metadata does not expose any field named `hash`, `content_hash`, or `payload_hash`.
  </behavior>
  <implementation>After compression and stored payload creation, group by exact `std::vector<std::byte>` stored payload only when `options.deduplicate` is true and `target.supports_shared_data_regions` is true. Assign numeric region IDs from first occurrence in sorted entry order. When dedup is disabled, always allocate a new region for every sorted entry even when stored payload bytes match.</implementation>
</feature>
