<feature>
  <name>Deterministic writer planning and validation</name>
  <files>src/writer.cpp, tests/writer_core_tests.cpp, include/libbsa/writer.hpp</files>
  <behavior>
    - Given entries `textures/z.dds` payload `{0x7a}`, `meshes/a.nif` payload `{0x61,0x62}`, and `textures/m.dds` payload `{0x6d}` in two different caller orders, `plan_archive_write` returns `entries` ordered exactly `meshes/a.nif`, `textures/m.dds`, `textures/z.dds` both times.
    - For raw-capable `writer_target{archive_format::fo4_ba2_gnrl, false, true, true, std::nullopt}` and `writer_options{false}`, each planned entry has `compression_state::raw`, `stored_size == size`, archive-absolute `offset`, and `total_size` equal to the last payload end.
    - The planner exposes `table_regions` exactly named `header`, `entry_table`, `data_region_table`, and `payloads`, with offsets/sizes derived from the byte contract that Plan 04 emits: 16-byte header; entry table as the sum of each entry record's fixed numeric fields plus its path bytes; data-region table as fixed records; payloads starting at the first planned data-region offset.
    - Duplicate normalized paths such as `Meshes/Armor/Iron.NIF` and `meshes\\armor\\iron.nif` return `error_code::malformed_archive` with message `duplicate writer path`.
    - Invalid empty path returns `error_code::malformed_archive` with message `invalid writer path`.
    - `writer_target{archive_format::unknown, false, true, true, std::nullopt}` returns `error_code::unsupported_format` with message `unsupported writer target`.
    - `force_compressed` with `supports_compression == false` returns `error_code::unsupported_format` with message `writer target does not support compression`.
    - A test seam that forces a near-`UINT64_MAX` table or payload cursor returns `error_code::malformed_archive` with message `writer layout overflow` rather than wrapping offsets or producing an impossible `total_size`.
  </behavior>
  <implementation>Sort normalized entries lexicographically by `archive_path::string()`, reject duplicates before map-like storage, resolve each entry's compression with `resolve_write_compression(target.format, entry.compression, target.archive_default_compressed)`, reject compressed states when `target.supports_compression == false`, call `resolve_payload_codec` and `compress_payload`, then compute checked layout with table regions named exactly `header`, `entry_table`, `data_region_table`, and `payloads`. Use archive-absolute offsets and central `checked_add` helpers returning `malformed_archive` / `writer layout overflow` on overflow. The sizing contract is shared with Plan 04 finalization: `entry_table.size` must be the exact byte count finalization writes for entry records, including variable path bytes, not a fixed-record-count approximation.</implementation>
</feature>
