# Quick Task 260514-11b Summary

## Result

Kept BA2 GNRL and TES4 raw writer finalization on the shared `host_file_path` seam so non-ASCII UTF-8 source paths no longer fall back to narrow `std::ifstream` reopens during archive publishing.

## Research

The existing Windows-safe seam was already in place: preparation resolved public UTF-8 host text into `detail::host_file_path`, but raw finalization still reopened only the saved string path. The minimal fix was to persist the resolved path in prepared raw entries and reopen through `detail::open_host_file(...)`.
