## Recommended Implementation

1. Add shared internal parser helpers in `src/detail/parser_primitives.hpp` and `src/detail/parser_primitives.cpp`.
   - Add generous internal constants for metadata entry count, BSA folder count, and BA2 DX10 aggregate texture chunk count.
   - Add `validate_metadata_count(...) -> result<void>` returning `error_code::format_error` for counts above a named limit.
   - Add template reserve helpers for metadata `std::vector<T>` and `std::unordered_set<T>` that catch only `std::bad_alloc` and `std::length_error` and translate them to `format_error`.
   - Include a short comment explaining that these are internal untrusted-archive metadata work limits, not public API behavior knobs.

2. Update TES3 BSA parsing in `src/formats/bsa/tes3_bsa_parser.cpp`.
   - Validate `header.file_count` immediately after header/version validation in both memory and host-file paths, before `table_size_for`, metadata table reads, or reserves.
   - Replace raw reserves in `read_file_records`, `read_name_offsets`, `read_names`, `read_hashes`, and `materialize_entries` with result-based metadata reserve helpers.
   - Reserve duplicate-detection sets for canonical paths and stored hashes before the insertion loop.
   - Add narrow `std::bad_alloc` / `std::length_error` translation around remaining archive-controlled metadata materialization growth if helper reserves do not cover it fully.

3. Update TES4-family BSA parsing in `src/formats/bsa/tes4_bsa_parser.cpp`.
   - Validate `header.folder_count` and `header.file_count` immediately after supported-header validation.
   - Validate each folder record `file_count` against the entry limit before per-folder file-record reservation.
   - Keep existing aggregate folder/file count validation.
   - Replace raw reserves in folder records, folder blocks, per-folder file records, file names, entries, and duplicate path set with result-based helpers.
   - Preserve existing TES5Edit compatibility comments and do not remove accurate comments.

4. Update BA2 GNRL parsing in `src/formats/ba2/ba2_gnrl_parser.cpp`.
   - Validate `header.file_count` in both `parse_ba2_gnrl_archive_impl` and `parse_ba2_gnrl_archive_file` after header/detected consistency checks and before record-size arithmetic, record reads, filename reads, or materialization.
   - Replace raw reserves in `read_records`, `read_names`, `read_names_from_file`, and `materialize_entries`.
   - Reserve duplicate path set storage before insertion.

5. Update BA2 DX10 parsing in `src/formats/ba2/ba2_dx10_parser.cpp`.
   - Validate `header.file_count` in both memory and host-file open paths before record/name parsing.
   - In `read_records`, maintain an aggregate parsed chunk count and reject when adding a record's `chunk_count` would exceed the internal DX10 chunk limit, before `record.chunks.reserve(...)`.
   - Replace raw reserves in `read_records`, `read_names`, `public_chunks_for`, and `materialize_entries`.
   - Reserve duplicate path set storage before insertion.
   - Keep aggregate chunk validation before public `texture_chunk_metadata` or entries are materialized.

6. Add focused tests.
   - Extend `tests/unit/parser_primitives_tests.cpp` for count-limit success/failure and deterministic metadata reserve failure where portable.
   - Extend `tests/unit/tes3_bsa_reader_tests.cpp` with excessive declared `file_count` coverage.
   - Extend `tests/unit/tes4_bsa_reader_tests.cpp` with excessive header `folder_count`, header `file_count`, and per-folder `file_count` coverage if existing oversized tests do not already assert the new specific limits.
   - Extend `tests/unit/ba2_gnrl_reader_tests.cpp` with excessive declared `file_count` coverage for in-memory/public open and host-file parser path where practical.

## Risks And Checks

- Limit values must be high enough for real archives but low enough for deterministic malformed tests; keep them internal and documented.
- `unordered_set::insert` can allocate even after `reserve`; use both pre-reserve helpers and narrow allocation catch boundaries for materialization paths.
- BA2 DX10 aggregate chunk-limit tests should fail during record parsing, before filename table or public texture metadata allocation.
- Do not modify anything under `TES5Edit/`.
