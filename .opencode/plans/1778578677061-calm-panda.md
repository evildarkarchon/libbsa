## Implementation Steps

1. Migrate bulk extraction test support in `tests/unit/bulk_extraction_tests.cpp` to the new coalesced-request contract.
- Replace or reshape `capturing_sink_factory` around the behavior the public API now promises: one sink creation per unique exact request path, request-order result records for all inputs, and mirrored duplicate outcomes.
- Update existing bulk extraction tests to use the migrated helper directly instead of preserving old helper methods solely for compatibility.
- Keep only test utilities that express observable public behavior, such as captured bytes for successful owning extractions and per-path sink creation counts.
- Add a small failing factory/helper for sink-factory failure scenarios if that is the clearest way to assert public failure behavior.

2. Add failing tests before implementation.
- Serial duplicate success: duplicate exact paths return one result per request in request order, mirror entry metadata, and create one sink for the duplicate path.
- Parallel duplicate success: same assertions with `worker_count > 1`.
- Duplicate missing path: all duplicate records get `error_code::not_found`, unrelated distinct paths still complete, and no sink is created for the missing path.
- Duplicate sink-factory failure: all duplicate records mirror the first failure, unrelated distinct paths still complete, and the factory is called once for the duplicate path.
- Distinct string control: paths such as `Meshes/Alpha.NIF` and `meshes\\alpha.nif` are not pre-merged even if archive lookup normalizes them to the same entry.

3. Refactor extraction dispatch in `src/archive.cpp`.
- Add a file-local helper that extracts payload from an already-found `entry_metadata` by dispatching to the existing TES3, TES4, BA2 GNRL, or BA2 DX10 reader functions.
- Use this helper from `extract()` and `extract_bytes()` after their existing lookup, preserving behavior while avoiding an extra lookup when metadata is already available.
- Use the same helper from bulk extraction so each unique bulk request performs archive lookup at most once.

4. Implement exact-string grouping in `archive_reader::extract_entries`.
- Preserve existing outer validation for unopened readers and `worker_count == 0`.
- Build first-seen request groups keyed by exact `bulk_extract_request::path` string, with each group storing the first request path and all original result indices.
- Do not normalize, lowercase, slash-convert, canonicalize, or compare entry metadata paths for grouping.
- Allocate the result vector at `requests.size()` so the returned shape remains one record per input request.
- Run `detail::run_indexed_work(groups.size(), options.worker_count, work)` instead of scheduling every original request index.
- For each group, perform `find`, sink factory `create`, null-sink validation, and payload extraction only for the first occurrence.
- Copy the first occurrence outcome to each grouped result index and explicitly set each result record's `path` from the corresponding original request.
- Keep per-entry failures local to the group and return success from the worker so unrelated groups continue processing.

5. Update public comments, thread-safety documentation, and documentation policy tests as a migration.
- In `include/libbsa/archive.hpp`, document that duplicate exact request paths share the first occurrence extraction result and only unique request paths call the sink factory.
- In `docs/thread-safety.md`, replace wording that implies every requested entry gets a sink with wording that says every unique extracted path gets a distinct sink, while duplicate request records mirror the first occurrence.
- Update `tests/unit/thread_safety_docs_policy_tests.cpp` to assert the new documentation contract instead of retaining old wording just to keep the previous token checks passing.

6. Mark OpenSpec tasks as they are completed.
- Update `openspec/changes/deduplicate-bulk-extract-requests/tasks.md` from `- [ ]` to `- [x]` immediately after each task is implemented or verified.
