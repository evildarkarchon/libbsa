## Case And Padding Policy

- Derive expected BA2 extension FourCCs from canonical parser paths, not original display paths, because existing BA2 parsers already canonicalize paths before hash validation.
- Encode the expected extension with the writer's printable ASCII plus NUL padding rule.
- Compare ASCII letters case-insensitively while preserving non-letter bytes and NUL padding exactly. This keeps existing synthetic archives with uppercase stored record extensions such as `BIN\0`/`NIF\0` valid for canonical `.bin`/`.nif` paths while still rejecting true metadata disagreements.
