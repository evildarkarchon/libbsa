## Current Code Shape

- Public API is in `include/libbsa/archive.hpp`; `ArchiveFormat` currently has `unknown`, `tes4`, `fo3`, and `sse`.
- `ArchiveReader::open()`, lookup, and extraction are implemented in `src/archive_reader.cpp` and currently always use TES4-family functions.
- `src/tes4_archive.hpp` exposes a format-neutral `detail::ParsedArchive`, `normalize_archive_path()`, `lookup_key_for_archive_path()`, and TES4 parse/extract functions.
- `src/tes4_archive.cpp` owns common path normalization, TES4 lookup key generation, whole-file loading, parsing, extraction bounds checks, and decompression.
- `src/binary_reader.hpp` already provides little-endian reads, seeking, skipping, and null-terminated string reads suitable for TES3 parsing.
- Tests use generated fixtures from `tests/fixture_builder.hpp/.cpp`; hash tests are in `tests/hash_tests.cpp` and archive integration tests are in `tests/archive_reader_tests.cpp`.
- `TES5Edit/` is read-only reference material. Relevant TES3 behavior was found in `TES5Edit/Core/wbBSArchive.pas`, especially `CreateHashTES3`, `FindFileRecordTES3`, and the `baTES3` load path.

## Implementation Steps

1. Public API and dispatch
   - Add `tes3` to `ArchiveFormat` in `include/libbsa/archive.hpp`.
   - Update public comments that still describe the reader or entries as TES4-only.
   - Add TES3 magic detection (`0x00000100`) in `ArchiveReader::open()` before TES4-family dispatch.
   - Include the new TES3 archive header in `src/archive_reader.cpp`.

2. TES3 hash module
   - Add `src/tes3_hash.hpp` declaring `std::uint64_t hash_tes3(std::string_view filename) noexcept` in `libbsa::detail`.
   - Add `src/tes3_hash.cpp` implementing BSArchPro-compatible `CreateHashTES3` behavior.
   - Use ASCII-only lowercasing, split the full normalized filename at `floor(len / 2)`, XOR the first half into the high dword, and XOR/rotate the second half into the low dword.
   - Add a short comment for the non-obvious rotate amount because BSArchPro derives it from `temp & 0x1F`, not directly from the byte offset.

3. TES3 parser module
   - Add `src/tes3_archive.hpp` declaring `parse_tes3_archive()` and `extract_tes3_entry()`.
   - Add `src/tes3_archive.cpp` using `BinaryReader`, `ParsedArchive`, `normalize_archive_path()`, and `hash_tes3()`.
   - Parse the TES3 layout in order: magic, `HashOffset`, `FileCount`, size/offset records, name offset table skip, null-terminated filenames, hash table, then data section.
   - Validate archive-controlled counts and offsets before allocating or seeking: truncated header, table overflow, name table bounds, hash table bounds, unterminated names, and data spans past EOF.
   - Treat `12 + HashOffset` as the absolute hash-table offset and seek there after reading names; reject offsets before the name records or past EOF.
   - Read hash table entries as two `uint32` values in spec order, high dword then low dword, combining `(uint64(high) << 32) | low`.
   - Populate `ArchiveMetadata` with `format = ArchiveFormat::tes3`, `version = 0`, zero flags, `folder_count = 0`, and the header file count.
   - Populate `ArchiveEntry` with normalized path, `folder_hash = 0`, TES3 file hash, absolute `data_offset = data_section_offset + record.offset`, raw sizes, no compression, and `CompressionMethod::none`.
   - Build TES3 lookup keys from the 64-bit TES3 hash using a TES3-specific key helper so TES4 key behavior is unchanged.

4. Shared reader lookup and extraction
   - Add a small internal helper in `archive_reader.cpp` to compute the lookup key based on `metadata.format`.
   - For TES3, normalize the path then hash with `hash_tes3()` and use the TES3 single-hash key.
   - For TES4-family archives, keep the existing `lookup_key_for_archive_path()` path unchanged.
   - In `extract()`, branch to `extract_tes3_entry()` for `ArchiveFormat::tes3`; otherwise call `extract_tes4_entry()`.

5. TES3 extraction
   - Implement `extract_tes3_entry()` as a raw byte copy from `entry.data_offset` for `entry.stored_size` bytes.
   - Enforce archive bounds and the same 512 MiB in-memory extraction ceiling used by TES4.
   - Do not apply embedded-name skipping, size-prefix handling, or decompression for TES3.

6. CMake wiring
   - Add `src/tes3_archive.cpp` and `src/tes3_hash.cpp` to the `libbsa` target in `CMakeLists.txt`.
   - Add `src/tes3_hash.cpp` to the `libbsa_hash_tests` target.
   - No dependency changes are needed.

7. Test fixtures
   - Extend the fixture builder with a dedicated TES3 fixture writer rather than forcing TES3 into the TES4-family fixture shape.
   - Add a simple TES3 fixture entry type or helper that stores full archive path plus payload.
   - Serialize the fixture as TES3: magic, hash offset, file count, size/offset table, name offsets, null-terminated normalized filenames, high/low dword hash table, then raw payloads.
   - Keep the fixture small and generated in the temp test directory, not under `TES5Edit/`.

8. Tests
   - Add TES3 hash vectors in `tests/hash_tests.cpp` for short names, odd/even lengths, nested paths, uppercase ASCII, slash-normalized input, and at least one non-ASCII byte case.
   - Add TES3 archive tests in `tests/archive_reader_tests.cpp` for metadata, entry listing, path normalization, `contains()`, `entry()`, `extract()`, `extract_to()`, missing-file errors, and byte-identical payload extraction.
   - Add detection tests proving TES3 magic is not routed to TES4 and existing `BSA\0` fixtures are still detected as TES4-family.
   - Add malformed TES3 tests for truncated header, invalid hash offset, unterminated filename, and payload span past EOF.
   - Keep existing TES4-family tests unchanged except where public comments or new enum assertions naturally need updating.

## Risks

- Hash table dword ordering is the highest compatibility risk. The OpenSpec requires high-dword then low-dword reads; implementation should follow that unless a real fixture contradicts it, in which case pause and update the artifact.
- `HashOffset` should not be ignored. Use it to locate the hash table robustly, while still validating that names and tables fit inside the archive.
- Existing `lookup_key_for_archive_path()` is TES4-specific. Do not generalize it in a way that changes TES4 lookup behavior.
- The current in-memory archive model is acceptable for this change; streaming extraction remains out of scope.
