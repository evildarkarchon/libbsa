## Research Conclusion

- `TES5Edit/Core/wbBSArchive.pas` confirms BA2 version 2 reads `Unknown1` and `Unknown2` and defaults to zlib.
- `TES5Edit/Core/wbBSArchive.pas` confirms BA2 version 3 reads `Unknown1`, `Unknown2`, and `CompressionMethod`, using LZ4 block when `CompressionMethod == 3`.
- `TES5Edit/Core/wbBSArchive.pas` routes version 3 to Starfield before checking `GNRL` versus `DX10`, so a v3 `GNRL` header is structurally accepted by the reference reader.
- `bsa-rs`/`ba2` accepts versions 1, 2, 3, 7, and 8 for `GNRL` and `DX10`; it treats v3 compression method `0` as zlib and `3` as LZ4.
- Wrye Bash research reports shipped Starfield general archives as v2 and texture archives as v3, so v3 `GNRL` appears valid but uncommon.

Recommended artifact correction before code edits:

- Update the BA2 GNRL spec supported-version set from `{1, 2, 7, 8}` to `{1, 2, 3, 7, 8}`.
- State that Starfield v2 defaults to zlib and Starfield v3 reads `CompressionMethod`, where `0` or unknown non-3 values use zlib and `3` uses LZ4 block.
- Keep `DX10` unsupported for this change even when the version is otherwise supported.

## Key Edge Cases

- Reject archive-controlled table sizes and offsets before allocating vectors.
- Keep extraction under the existing 512 MiB in-memory limit pattern used by TES3/TES4.
- Return `unsupported_format` for supported-version `DX10`, because DDS BA2 is out of scope.
- Return `unsupported_format` for unknown BA2 versions outside 1/2/3/7/8.
- Return `malformed_archive` for duplicate BA2 hash triplet lookup keys.
- Preserve current TES3/TES4 behavior and tests.
