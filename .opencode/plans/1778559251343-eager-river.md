## Goal
Make `tes3_bsa_writer`, `tes4_bsa_writer`, `ba2_gnrl_writer`, and `ba2_dx10_writer` move-only owners of their staged mutable writer state. Prevent public writer copies from aliasing entries, options, or BA2 DX10 snapshot ownership while keeping archive output behavior unchanged.

## Implementation Steps
1. Update the public writer API in `include/libbsa/writer.hpp`.
   - For each of the four writer classes, declare a public destructor, deleted copy constructor, deleted copy assignment, move constructor, and move assignment.
   - Add tight Doxygen comments documenting move-only ownership transfer and moved-from validity for destruction or reassignment.
   - Change each private `state_` from `std::shared_ptr<state>` to `std::unique_ptr<state>`.

2. Update writer implementations to use exclusive PIMPL ownership.
   - Replace each `std::make_shared<state>` construction with `std::make_unique<state>`.
   - Define the destructor, move constructor, and move assignment out-of-line after each concrete `state` definition so `std::unique_ptr<state>` sees a complete type.
   - Do not change add-entry validation, options accessors, compression routing, or `write_to` logic except for following the unique owner.

3. Preserve BA2 DX10 snapshot ownership semantics.
   - Keep `ba2_dx10_writer::state::~state()` as the only snapshot cleanup path.
   - Rely on `std::unique_ptr` move semantics to transfer snapshot directory ownership to the moved-to writer.
   - Avoid new cleanup flags unless verification exposes a concrete duplicate-cleanup issue.

4. Add focused writer ownership tests.
   - Create `tests/unit/writer_ownership_tests.cpp` and register it in `tests/CMakeLists.txt`.
   - Add `static_assert` coverage proving all four writer classes are not copy constructible, not copy assignable, move constructible, and move assignable.
   - Add runtime move-construction and move-assignment tests proving moved-to writers can finalize staged entries.
   - Keep runtime tests small: TES3/TES4/BA2 GNRL can stage memory entries and reopen with `archive_reader`; BA2 DX10 should stage one generated DDS source and verify reopened texture extraction/metadata.
   - Do not call operational methods on moved-from writers.

5. Review thread-safety documentation.
   - If needed, update `docs/thread-safety.md` from generic independent-writer wording to clarify that separately constructed or moved-to writer objects may be used concurrently.
   - Keep the change minimal and do not remove accurate existing comments or documentation.

6. Mark OpenSpec tasks as complete as implementation proceeds.
   - Update `openspec/changes/prevent-writer-copy-aliasing/tasks.md` immediately after each corresponding source/test/doc/verification task is actually complete.
   - Do not mark verification tasks complete until the relevant commands pass.

## Risks And Checks
- `std::unique_ptr<state>` with incomplete `state` requires out-of-line destructor and move definitions. Do not default these inline in the header.
- Move assignment of a BA2 DX10 writer will destroy any destination-owned state first, which should trigger best-effort cleanup for the destination's old snapshot directory exactly once.
- Existing public writer tests should continue passing without expectation changes; any archive-output changes are suspect.
- `TES5Edit/` is read-only and must not be modified, formatted, staged, or used as mutable test data.
